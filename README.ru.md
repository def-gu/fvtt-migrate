# fvtt-migrate

Переносит установку Foundry Virtual Tabletop с одной машины на другую и после
переноса сверяет копию с источником.

Программа ничего не записывает и не удаляет в той установке, откуда копирует.
Лицензионный ключ и хеш пароля администратора лежат вне области, к которой она
обращается, и это закреплено тестом.

[English version](README.md)

## Что понадобится

Программа нужна на обеих машинах. Скачайте файл для своей системы на странице
релизов.

- Windows, `fvtt-migrate-windows-amd64.exe`
- Linux, `fvtt-migrate-linux-amd64`
- Linux на ARM, `fvtt-migrate-linux-arm64`
- macOS, `fvtt-migrate-darwin-arm64`

В Linux и macOS один раз разрешите запуск.

```
chmod +x fvtt-migrate-linux-amd64
```

Проверьте, что программа отвечает.

```
fvtt-migrate version
```

Ещё нужен путь к пользовательскому каталогу Foundry. Это папка, внутри которой
лежат `Data`, `Config` и `Logs`. Обычные места такие.

- Windows, `%LOCALAPPDATA%\FoundryVTT`
- Linux, `~/.local/share/FoundryVTT`
- macOS, `~/Library/Application Support/FoundryVTT`

Перед началом верните Foundry на экран настройки. В открытый мир идёт запись, и
копирование во время записи его повредит. Программа это проверяет и откажется
работать, а не сделает битую копию.

## Шаг 1. Посмотреть, что есть

```
fvtt-migrate scan --root /путь/до/FoundryVTT
```

Команда только читает и печатает. Она ничего не меняет и никуда не обращается.

В ответе будет число миров, систем и модулей, сколько данных используется на
самом деле, и два списка, которые стоит прочитать. Первый, битые ссылки. Второй,
миры, чья игровая система не установлена. Такой мир на новом месте не откроется,
поэтому программа оставит его на источнике.

## Шаг 2. Решить, что переносится

```
fvtt-migrate plan --root /путь/до/FoundryVTT
```

Команда создаёт файл `plan.yaml`. Откройте его и прочитайте. Ничего ещё никуда
не уехало.

В плане записано, какие миры едут, откуда берётся каждый модуль и какие папки с
файлами включены. План можно править. Если правка окажется неверной, следующий
шаг откажется работать и назовёт место ошибки.

Чтобы заодно узнать у источников модулей, какие версии доступны сейчас,
добавьте флаг.

```
fvtt-migrate plan --root /путь/до/FoundryVTT --check-updates
```

Без этого флага с машины не уходит ничего. С ним читаются только манифесты
пакетов.

Если вы переезжаете на другое поколение Foundry, укажите это. Целевая версия
меняет все рекомендации в плане.

```
fvtt-migrate plan --root /путь/до/FoundryVTT --target-core 14.363
```

## Шаг 3а. Перенос в другую папку или на другой диск

Простой случай, с него стоит начать.

```
fvtt-migrate apply --root /путь/до/FoundryVTT --to /путь/до/назначения
```

Чтобы увидеть, что произойдёт, ничего при этом не записывая, добавьте
`--dry-run`.

## Шаг 3б. Перенос на сервер через интернет

На сервере запустите принимающую сторону. Она слушает саму машину, а наружу
смотрит ваш обратный прокси. Ключ доступа программа выдаст сама и напечатает
вместе с готовой командой для второй машины.

```
fvtt-migrate serve --to /srv/foundry-data --listen 127.0.0.1:7788
```

Направьте прокси на `127.0.0.1:7788`. В nginx нужно поменять три настройки,
иначе загрузка откажет сразу с ошибкой 413.

```nginx
location / {
    proxy_pass http://127.0.0.1:7788;

    client_max_body_size 0;
    proxy_request_buffering off;
    proxy_read_timeout 3600s;
    proxy_send_timeout 3600s;
}
```

Для Caddy достаточно обычного `reverse_proxy 127.0.0.1:7788`.

Порт 7788 в файрволе открывать не нужно. Единственный вход снаружи, это прокси.

На своей машине задайте тот же ключ и укажите адрес с `https`.

```
export FVTT_MIGRATE_TOKEN=<тот же ключ>
fvtt-migrate apply --root /путь/до/FoundryVTT --to https://ваш.домен
```

Ключ задавайте переменной, а не аргументом команды. Аргументы видны всем
пользователям машины.

Если связь оборвалась, запустите ту же команду снова. Она продолжит, а не
начнёт заново. Принимающая сторона помнит, что у неё уже есть, поэтому второй
запуск отправляет только новое.

## Шаг 4. Убедиться, что получилось

Этот шаг нужен для уверенности в результате, поэтому его не пропускают.

```
fvtt-migrate verify --root /путь/до/FoundryVTT --to /путь/до/назначения
```

Для сервера так.

```
fvtt-migrate verify --root /путь/до/FoundryVTT --to https://ваш.домен
```

Каждый мир открывается с обеих сторон, и в нём считаются документы. В каждой
строке должно стоять одно и то же число дважды.

```
Worlds
  puti-azlanti      source=57078   target=57078   ok
```

Копия может разложить все файлы и при этом оставить мир пустым. Счёт документов
находит именно такой случай, поэтому он вынесен в отдельный шаг, и поэтому
печатаются числа, а не галочка.

Чтобы вдобавок перечитать на приёмнике каждый байт, добавьте `--deep`. Это
займёт столько же времени, сколько занял перенос.

## Если что-то пошло не так

`world "..." is loaded in Foundry`
Вернуть Foundry на экран настройки и запустить снова.

Ошибка `413` от сервера
Прокси ограничивает размер тела запроса. Настройки nginx приведены выше.

`sends the token in the clear`
Указать адрес с `https`, а не с `http`.

`a token is required for a remote target`
Задать `FVTT_MIGRATE_TOKEN` на обеих машинах одинаковым.

`the plan has errors`
Строка и причина напечатаны выше сообщения. Поправить `plan.yaml` и запустить
снова.

`N source files changed during the copy`
В установку что-то писало во время чтения. Закрыть Foundry и запустить снова.

`verification failed`
Перечисленные миры доехали не целиком. Запустить `apply` снова, он дошлёт
недостающее.

## Чего программа не делает

- Не изменяет, не перемещает и не удаляет ничего в источнике.
- Не читает `Config/license.json` и `Config/admin.txt` и отказывается их
  переносить.
- Не выходит в сеть без флага `--check-updates` или адреса назначения с `https`.
- Не обновляет ничего по своему усмотрению. Каждая смена версии сделана вашим
  решением в `plan.yaml`.

## Графическая панель

Если не хочется набирать команды, запустите панель. Всё, что делают шаги выше,
доступно в ней.

```
fvtt-migrate panel --root /путь/до/FoundryVTT
```

Затем откройте в браузере `http://127.0.0.1:7788/`. Панель останавливается
закрытием окна, в котором запущена команда.

Панель отдаётся только на этой машине, потому что своего пароля у неё нет.

Она читает вашу установку и показывает одну страницу. Сверху целевая версия
Foundry, это управляющий элемент, а не подпись, потому что её смена
пересчитывает все решения ниже. Дальше ваши миры, причём те, что не откроются на
новом месте, выключены, и причина названа. Дальше все пакеты, разобранные по
тому, что с каждым следует сделать. Дальше файлы, и отдельно выделена папка, у
которой устарели пути.

Внизу указывается назначение. Путь до папки на этой машине либо адрес приёмника
с `https` вместе с ключом доступа, который тот напечатал при запуске. Затем две
кнопки. Первая считает, что поедет, и ничего не записывает. Вторая начинает
перенос.

Во время переноса панель называет текущую фазу и показывает рядом отправленное и
пропущенное, потому что на той стороне это уже было. Остановка безопасна в любой
момент.

По завершении панель предложит проверить результат. Проверка открывает каждый
мир с обеих сторон и считает документы, то же самое делает команда `verify`.

## Сборка из исходников

Нужна только тем, кто меняет саму программу. Требуются Go 1.26 и Node 20.

```
./build-panel.sh
go build ./cmd/fvtt-migrate
```
